==================================================
一、项目定位与必须保留的核心
==================================================

1. 名称：星河交汇 STELLAR NEXUS。
2. 核心目的：群体学习＋AI辅助。让人们找到共同学习的人，在活动中实践与交流，再把经验转化为公共知识和个人积累。
3. 申请方向：信息管理与网络技术。重点展示信息架构、知识组织、数据库与接口、跨用户协作、权限、状态管理和知识图谱，不转向教育学或社会学申请定位。
4. 成年人可以同时“我想学”“我可以教”，也可针对某项技能选择“两者皆可”。不固定谁教谁，不按年龄默认配对，不要求先交换技能才能参加。
5. 支持一群人一起学、多位分享者共同带领；不能退回只有一对一师徒匹配，也不能做成普通课程商品商城。
6. 线上持续存在，线下空间按活动条件安排，无固定自营门店。真实场地许可由组织者取得并确认，系统不冒充已完成预订。
7. 主循环：兴趣与需求 → 形成小组与活动 → 共同学习与记录 → 个人整理复习／授权公共分享 → 新的学习与贡献。
8. AI贯穿学习前、中、后，围绕具体资料与任务提供帮助；不只是在页面角落添加一个通用聊天框。

==================================================
二、最终六个主入口与页面归属
==================================================

主导航顺序固定为：
① 知识星河
② 群体活动
③ 公共知识库
④ 我的星河
⑤ 知识观星台
⑥ 系统设置与账号管理

第五项正式定名为“知识观星台”。不再使用“需求雷达”“学习风向”或单独的“观星台”作为正式导航名称。
第六项可在较窄界面显示“设置与账号”，完整页面标题为“系统设置与账号管理”。

管理员工作台为权限限定的辅助入口，不作为面向所有人的第七个主模块。

归属规则：
- 活动详情位于“群体活动”内，由活动列表进入。
- 分享者介绍嵌在活动详情中；详情可跳转其公共导师主页。
- 场地选择位于“群体活动”的发起／组课／管理流程内；普通参与者主要查看已确认场地。
- 明星导师与导师成长入口位于“公共知识库”。
- 私人知识库、AI知识整合、个人复习和学习时间线位于“我的星河”。
- 当前需求、供需缺口和组课机会保留为独立“知识观星台”。
- 线下概念场景作为活动与项目介绍的辅助内容，不再独占一级导航。
- 原“知识整理”拆分：私人整理进入我的星河；公共内容浏览与发布管理进入公共知识库；活动共同笔记从活动详情进入。

==================================================
三、知识星河：星河形态的可操作知识图谱
==================================================

知识星河不是只有星点的装饰背景，也不是普通圆形轨道图。它应是一条具有弯曲流向、疏密变化、交汇与延伸的知识银河。

1. 主体视觉：多股由七色知识光点构成的星流，在交汇处连接，再向外延伸。保持白底、清楚标签与可操作性，不采用暗黑宇宙或霓虹电竞风。
2. 节点类型：兴趣／技能、知识主题、公开知识、学习小组／活动。人物可在节点详情或关联展开中出现，避免首次进入就混入大量人像节点。
3. 关系类型：主题归属、关联实践、先修关系、活动产出、共同学习关联。只有数据支持的关系才绘制；AI建议的关系须标明“建议关联”，不能冒充已确认关系。
4. 状态：我想学、我可以教、两者皆可、正在学习、已有活动、暂缺分享者等，用文字、图标、外环或线型辅助表达。
5. 七色表达多样参与者与经验，不固定对应年龄、性别、能力或教师／学员身份。不再用“蓝色＝学、橙色＝教”作为全站角色编码。
6. 点击主题后打开详情或逐层展开：子主题、相关知识、活动、公开分享者与学习需求。示例：手机摄影 → 构图／光线／人像／后期。
7. 支持关键词搜索、类别／地区／角色／活动状态筛选、放大缩小、重置与文字列表替代。
8. 节点多时按主题聚合并逐层展开；节点大小如代表活跃度，必须说明计算口径，不能只为好看而暗示热度。
9. 公共图谱仅出现已审核、已授权的公开内容。私人兴趣和笔记只出现在用户自己的视角，不因与公共主题关联而公开。
10. 空状态：区分公共演示星河与用户自己的星河；未保存个人兴趣时不得呈现虚假的个人积累。

首次引导保留：
可跳过的星河开场 → 分类搜索／多选／自建兴趣 → 分项设置学／教／两者皆可及条件 → 星河预览 → 登录保存 → 条件匹配与下一步。

开场约2–4秒，可直接进入浏览；遵守prefers-reduced-motion；不强制先注册。自建兴趣先保存为私人待审标签，同名优先复用，审核后进入公共分类。

==================================================
四、群体活动：列表、详情、分享者与场地一体化
==================================================

建议子入口：探索活动／我的活动／发起与组课。

A. 活动列表
- 以具体学习任务与成果为核心，不再主要使用泛化宣传语。
- 显示主题、成果或操作封面、日期与时段、城市或线上形式、适合程度、人数与状态、分享者摘要。
- 支持主题、地区、时间、形式、学习程度、活动状态等筛选；筛选结果可清除，有明确无结果状态。
- 标题示例：手机摄影入门：窗边人像与曝光练习；AI工具入门：整理笔记与核对来源；低压小灯维修：接线检查与故障排查。

B. 活动详情（从列表进入，有可返回路径）
1. 这次学什么：目标、适合谁、最后可完成的作品或任务。
2. 怎么一起学：人数、分组方式、教师分工、共同练习和讨论安排。
3. 谁来带领：本场分享者介绍、技能、经验、作品、相关公开知识；支持多位共同带领。
4. 在哪里进行：已确认场地、照片、容量、设备、交通与参加要求；线上活动展示所需工具。
5. 参加与准备：报名、候补、材料清单、活动前准备或小任务。
6. 活动后留下什么：共同笔记、成果、已授权图片及经核对的知识卡。

C. 发起与组课中的场地选择
- 组织者在活动模块内比较空间，不创建独立主导航。
- 场地信息含全景、桌面与设备图片、容量、可用时段、使用条件、申请／确认状态。
- 检查人数、地区、线上线下形式、设备与风险、时段冲突。能自动判断与必须人工核对的条件须区分。
- 确认获得许可后才开放招募；未确认时不显示“预约成功”。
- 私人住宅仅能在完整实现成年人邀请制、场地主同意和地址授权后开放；在此之前保持受限，不公开地址，不推荐高风险活动进入住宅。

D. 活动协作与状态
- 待匹配／待确认／招募中／已满员／已结束／已取消的产品状态与数据库枚举对应清楚。
- 保留重复报名限制、容量控制、候补及取消后递补、签到、反馈。
- 支持共同教师关系，并新增共同带领邀请／确认界面；不能仅靠种子数据表现多人师资。
- 共同笔记支持贡献者记录；不愿拍照、录音或公开笔记者仍可参加活动。
- 如尚未实现扫码签到，只展示已实现的活动码，不把装饰二维码当实际功能。

==================================================
五、公共知识库：知识、导师与本地文化
==================================================

建议三个栏目：知识与主题合集／导师与分享者／本地学习与文化。

A. 公开知识
- 以成果、步骤、屏幕截图、工具细节、前后对比等具体信息呈现，不再统一用大图标＋渐变背景作封面。
- 不同内容采用不同形式：图文教程、步骤清单、经验总结、活动共同笔记、主题合集。
- 知识卡包含：标题、技能标签、目标、关键步骤、适用条件、注意事项、作者与贡献者、关联活动、来源、确认／审核状态、更新时间及公开授权。
- 详情允许查看来源和更正信息；能保存到私人库，保存后仍保留出处，不冒充个人原创。
- 作者可更正、撤回授权和删除；公共可见性与授权状态同步。
- 公开浏览区优先展示知识；编辑流程、待审事项和我的草稿放入对应任务区域，减少长流程说明占据首页。

B. 明星导师与成长路径
- 公共知识库可介绍明星导师，展示代表技能、作品、共同带领经验、已发布知识和真实反馈。
- 普通成员可沿“参与学习 → 分享经验 → 协助带领 → 发布有帮助的知识 → 获得专题推荐”的路径成长。
- 推荐依据综合贡献质量、持续性、协作和帮助他人的情况，不只按点赞、报名量或关注数。
- AI可以整理贡献档案、辅助完善个人介绍、发现候选与相关主题；不能独立断言导师资质或给出无依据的能力认证。
- 推荐需人工核对并征得本人同意。可退出推荐，不把公开展示变成参与前提。
- 明星导师不是固定阶层；被推荐者也能继续学习，普通成员同样可以发起小组分享。
- 演示人物、作品与反馈必须标明示例，不虚构现有平台已培养导师的成果。

C. 本地学习与文化
- 展示地方技艺、文化活动、地方经验、作品与知识，以及这些主题在本地区的近期学习变化。
- 把“文化内容是什么”与“有多少人近期关注”结合，而不是只放柱状图或泛化地方介绍。
- 标明地区、时间范围、来源和统计口径；样本不足时使用“近期学习动态”，不冒称城市文化总体趋势。
- 可从主题进入相关知识、导师、活动与知识观星台的需求视图。

==================================================
六、我的星河：私人知识库＋AI整合＋复习＋时间线
==================================================

建议栏目：我的知识／AI整理／个人复习／学习时间线；兴趣管理、作品和参与记录融入这些视图。

A. 私人知识库
- 保存自己的笔记、活动材料、个人作品、疑问、收藏的公共知识和相关链接。
- 提供主题分类、标签、搜索、集合与关联；区分原创、收藏引用、共同贡献、AI草稿。
- 私人内容默认仅本人可见；加入收藏、建立关联或使用AI，不等于授权公开。
- 支持编辑、导出、删除以及按资料范围决定是否允许AI处理。

B. AI知识整合
- 用户选择资料后，再执行合并主题、整理结构、标记重复、关联来源、提取待确认问题等操作。
- 显示用了哪些资料，输出可编辑；区分原始内容、AI概括、AI建议与用户确认。
- 不自动补出不存在的事实，不把来源间矛盾静默合并成确定结论。
- 公共知识更新或撤回时，个人收藏应保留来源状态提示，不继续误示为当前有效的公开版本。

C. 个人复习
- 基于用户选定的内容生成复习卡、提问、小练习和复习安排。
- 用户可标记掌握／不确定／需要再练，调整或关闭提醒。
- 将复习联系到可完成的小任务，而不只是自动生成测验。例如：同一扇窗拍摄三个位置，比较人像光线。
- 没有真实LLM或调度服务时，展示明确的示例复习流程，不声称后台正在自动处理或发送提醒。

D. 学习时间线
- 汇总活动参与、笔记修改、练习完成、作品、知识发布及贡献记录。
- 支持按主题、时间和记录类型查看，从事件跳回原始资料。
- AI辅助梳理阶段总结、尚未解决的问题及下一步建议；用户确认后保存。
- 不只展示报名流水，不用虚构的连续学习天数或“能力提升百分比”制造成果。

E. 公私转换
私人笔记 → 用户主动选择分享 → 核对与补充来源 → 选择授权范围 → 教师／相关贡献者确认 → 公共审核与发布。
公共知识 → 保存到私人库 → 保留来源 → 加入个人理解与练习 → 个人复习与时间线。

七、知识观星台：独立观察当前需求与供需变化
==================================================

正式名称：知识观星台。
建议栏目：学习需求／分享力量／本地动向／组课机会。

1. 学习需求：目前大家想学什么、需求人数、方便的时间与地区、公开求课主题。
2. 分享力量：各主题可教者数量、公开技能与可进一步联系的候选；实际意愿和时段仍需确认。
3. 供需缺口：有需求无分享者、有分享者未开课、报名额满与候补积压、场地或设备限制。
4. 本地动向：按城市、行政区、主题和时间范围查看近期变化；提供可读的样本量及口径。
5. 组课机会：基于主题、程度、城市、形式、时段、人数组合、教师和场地限制提出可解释候选，由组织者决定执行。
6. 直观展示当前需求，不能只有一句AI总结，也不能隐藏统计依据。
7. 知识星河负责看见关联；知识观星台负责看见当前需求、缺口与变化；两者可相互跳转。
8. 公共知识库的文化栏目侧重内容、作品与传承经验；本页侧重参与需求和数据变化，不重复整套文化内容页。
9. 未积累足够历史快照时不声称精准预测；没有样本时显示空状态并提供发布需求入口。
10. 不公开他人私人笔记、精确住址或个人学习弱项；统计以聚合数据呈现。

八、系统设置与账号管理
==================================================

1. 个人资料：昵称、简介、城市、兴趣及公开分享资料。
2. 账号：登录、退出、账号安全和已实际支持的恢复方式；未实现的功能不得假成功。
3. 隐私与权限：公开资料、导师展示、图片／录音授权、私人知识的AI使用范围及撤回。
4. 通知：活动变化、候补递补、复习和贡献审核等偏好；仅启用已接通的通知渠道。
5. AI偏好：按资料选择处理范围、默认保留原始内容、处理模式说明；密钥不得在前端或交付包暴露。
6. 界面：字号、减少动态、图谱与列表偏好。
7. 数据：导出个人资料、私人知识、学习时间线；资料删除与授权记录的保留边界需说明。
8. 演示说明与能力状态放在可找到的位置；动作发生处保留必要简短提示，不让开发说明主导浏览页面。

==================================================
九、AI辅助的完整分工
==================================================

学习前：汇总学习需求，辅助形成目标与小组建议，准备材料清单与练习。
学习中：经许可整理共同笔记、归纳问题、标记未解决事项；涉及录音或图片必须先获得授权。
学习后：整合私人知识、辅助公共知识草稿、生成复习与小练习、梳理个人时间线。
贡献成长：辅助整理作品、贡献与教学经验，供本人核对和人工推荐。

必须分开标明：真实AI已接入／规则计算／结构化範本演示／规划中。
没有服务端API密钥时，仍可运行规则和範本演示，但不能伪装成真实模型推理。
LLM不替代人数和场地硬限制、权限检查、来源核对或人工场地许可。
生成任务需要加载、取消或失败反馈；未完成时不可显示成功或覆盖原始笔记。

==================================================
十、Logo与七色星河：最新品牌要求
==================================================

1. Logo主体是“星河”，不是行星轨道，不是单一中心星，也不是明显的书本／学校徽章。
2. 采用多股知识光点构成的流线，来自不同方向，交汇后继续延伸，形成紧凑完整的银河符号。
3. 多股流线表达群体共同学习，光点表达每个人的知识与经验；避免只有一个巨大中心、其他人围绕它的结构。
4. 使用柔和、清晰的七色，表达多样的人与经验共同组成银河。不要简单堆成七根平行彩虹条，也不要做成过于儿童化的彩虹贴纸。
5. 七色在流动与交汇中保持各自辨识度，不全部混成灰色；同时保证缩小时仍先看见一个完整符号。
6. 不把七色固定绑定年龄、性别、能力、教师与学员。角色用文字、图标或节点外环表达，不能只依赖颜色。

确认的七色基础值：
珊瑚红 #E87878

==================================================
十一、照片、内容和UI改版要求
==================================================

A. 修复已经发现的问题
- 停止在活动卡片中共用六宫格大图、通过背景定位截取，避免人物横向变形与露出分隔线。
- 每张卡片使用独立图片；固定适合的比例（活动列表可优先试16:10，按实测确定），保持等比裁切，允许逐图设置焦点。
- 检查桌面三列／中等宽度两列／手机单列下的图片，不出现露边、拉伸、主体被无意义切掉。
- 图片与课程一致：手机摄影呈现手机操作或对应摄影成果，不以手持单反的教师合照代替全部说明。

B. 补充更具体的真实摄影素材
- 活动：学习成果、实际操作、工具细节与不同场景，不重复同一种木桌围坐合照。
- 兴趣：摄影、咖啡、木工、电子等主题细节，用小图增强辨识，不牺牲选择效率。
- 知识：步骤、成果、屏幕截图、前后对比；没有合适图片时采用紧凑文字卡，不能拿巨大通用图标填空。
- 分享者：获授权的人像、作品和经验；导师形象与具体技能连接。
- 场地：全景、桌面、设备、入口与必要条件。
- 我的星河：自己的作品、笔记与参与记录，形成个体差异。
- 可以参考真实平台的展示逻辑；不直接挪用未经许可的活动照片，也不将素材照片冒充本平台实录。
- 建立素材清单：来源、作者、许可／用途、示意或实录、对应页面。AI理想场景仍清楚标注，主要用于线下概念呈现。

C. 页面层级与文案
- 主标题先说明具体任务或内容，抒情文案只作辅助。
- 加深重要正文、日期和关键条件；减少浅灰蓝文字铺满全页。
- 活动、人物、知识、场地、时间线采用各自适合的版式，不全部套同一种巨大圆角卡片。
- 缩减占空间的重复流程图和开发提示；首次指引可展开，日常浏览优先显示内容与操作。
- 活动列表便于比较，知识库便于发现与阅读，我的星河便于整理与复习，观星台便于看见需求。
- 保留清楚字号、足够对比度、键盘操作、可见焦点、对话框关闭与错误恢复。

十二、数据与技术的后续调整
==================================================

保留V1的users、profiles、skills、skill_categories、custom_skill_submissions、user_skills、learning_requests、courses、events、event_teachers、registrations、venues、venue_availability、session_records、knowledge_cards、knowledge_sources、contributions、consent_records、skill_demand_snapshots，以及sessions、event_feedback。

根据新功能新增或扩展以下实体；命名可随实现调整，但关系与权限不能省略：
- graph_nodes / graph_edges：节点类型、关系类型、来源、建议／确认状态与公开范围。
- private_knowledge_items：所有者、资料类型、内容、来源、主题、可见性与更新时间。
- knowledge_collections / collection_items：私人或公共合集及条目关系。
- saved_knowledge：收藏者、原知识卡、引用版本、来源状态。
- review_cards / review_sessions：复习内容、原资料、掌握状态与练习记录。
- learning_timeline_entries：记录类型、时间、主题、关联活动／作品／知识及可见性。
- ai_jobs / ai_job_sources：任务、模式、状态、所选资料、输出与用户确认。
- mentor_profiles / mentor_nominations：公开介绍、推荐依据、人工审核、本人同意与退出状态。
- local_topic_snapshots：地区、时间窗口、主题、样本量与统计口径。
- user_preferences：通知、显示、AI处理与隐私偏好。
- media_assets：独立图片、来源、授权范围、示例／实录标记与裁切焦点。

私人内容必须在服务端按所有者隔离；不能只在前端隐藏。不因进入共同主题图谱、被AI处理或被收藏而改变权限。
数据库迁移保留现有资料，新增迁移，不重放或改写已应用迁移。动态数字来自数据库，不写死成虚假社会统计。

十三、实施顺序与验收
==================================================

第一阶段：结构与视觉修复
- 六入口与正式名称统一；正确嵌套活动详情、分享者、场地。
- 七色星河Logo与开场方向落地；角色不再只用蓝橙编码。
- 独立图片替换拼图背景；活动与知识内容更具体。
- 重做活动列表、公共知识库和我的星河的布局层级。

第二阶段：群体学习与个人知识闭环
- 场地与组课、共同教师、活动记录、知识公私转换。
- 私人知识库、收藏引用、个人学习时间线、可操作复习。
- AI整理有来源、确认、失败和权限处理；无真实API时明确演示。

第三阶段：贡献成长与本地观察
- 明星导师介绍与成员成长／推荐流程。
- 知识观星台的当前需求、供需缺口、地区与时间筛选、组课候选。
- 公共知识库的本地文化内容与观星台数据互相连接。

必须跑通的验收场景：
A. 访客开场 → 自建／选择兴趣 → 学教双角色 → 登录保存 → 图谱与匹配。
B. 活动列表 → 活动详情 → 查看分享者与条件 → 报名／候补 → 签到 → 活动记录。
C. 发起组课 → 比较并确认场地 → 多位带领者 → 招募 → 状态变化。
D. 活动笔记 → 私人知识库 → AI整合／人工确认 → 复习小任务 → 时间线留痕。
E. 主动分享 → 来源核对与授权 → 审核发布 → 其他成员收藏引用 → 更正／撤回状态同步。
F. 普通成员贡献 → 导师档案 → 推荐审核与同意 → 明星导师展示。
G. 知识观星台 → 发现本地供需缺口 → 查看数据依据 → 发起求课或组课。
H. 不同账号不能读取对方私人笔记、复习弱项或未授权原始记录。
I. 三种主要屏幕宽度图片无变形、分隔线、露边；列表与图谱均可操作。

V1的30项本地后端测试不等于以上V2场景已通过。应针对新增关系、权限、公私知识与撤回传播进行验收，再更新测试报告。
